# Deployment files (reference, not production-ready)

* `docker-compose.yml`, `docker/` – 3 core nodes with quorum election, cim-pds, EMS, historian (PostgreSQL), FEP, Redis Streams bus. Run `./make-secrets.sh` first, build `ui` (`npm run build`) and the `pki` tool.
* `helm/gridsovereign` – the same as a chart: core as a 3-replica StatefulSet (node id = pod ordinal, anti-affinity, PodDisruptionBudget `maxUnavailable: 1`), other services as Deployments, default-deny NetworkPolicy, read-only root file systems, dropped capabilities, secrets from one pre-created Secret. Create the secret with `OUT=s CORE_IDS="0 1 2" ./make-secrets.sh` and `kubectl create secret generic gridsovereign-secrets --from-file=s/`.

**What has and has not been verified.** The YAML files parse, the Helm templates were only checked for balanced actions (no `helm` binary and no container runtime in the build environment), so neither the compose file nor the chart has been started and the Dockerfiles have not been built. The command lines and environment variables they use are the ones `tools/stack.sh` runs and the code reads (`*_FILE` secrets for `GS_SECRET` and `HIST_DSN` were added for this and are covered by the normal suites, not by a container run). Not covered: the outstation simulator (dev only), the mTLS proxy sidecars (the stack option `GS_MTLS` exists, no chart wiring), TLS on the Redis link, Redis/Postgres high availability (use managed HA services), image signing, and an ingress with TLS (`ingress.enabled` is a flag with no template yet).
